Was der Mod kann

Sechs Dinge, mehr nicht.

Autobuild GUI ist bewusst klein: Es liest, was Litematica geladen hat, prüft dein Inventar und gibt den Auftrag an Baritone weiter. Alles andere machen die beiden selbst.

Hotkey

Menü auf Tastendruck

B öffnet die Liste — mitten im Spiel, ohne Chat-Befehl. Die Taste ist frei belegbar unter Optionen → Steuerung.

Übersicht

Alle Placements auf einen Blick

Jede Zeile zeigt Name, Maße und Blockanzahl. Das Suchfeld filtert live nach Namen — auch bei zwanzig geladenen Schematics.

Material-Check

Sagt vorher, was fehlt

Reicht das Inventar nicht, steht „N Blöcke fehlen" in der Zeile und der Klick ist gesperrt — statt mittendrin steckenzubleiben.

Ein Klick

Klick startet den Bau

Baritone bekommt genau dieses Placement, das Menü schließt sich. Keine Index-Rechnerei, kein #build mit Koordinaten.

Kontrolle

Laufanzeige mit Abbruch

Das laufende Placement zeigt beim erneuten Öffnen einen Balken und ein rotes ✕. Es läuft immer nur ein Build; ein neuer bricht den alten sauber ab.

Robust

Stürzt nicht ab, wenn was fehlt

Ohne Litematica oder Baritone öffnet sich das Menü trotzdem und sagt in Klartext, welcher Mod fehlt. Beide sind echte Soft-Dependencies.

So funktioniert es

Drei Mods, eine Kette.

Autobuild GUI platziert keinen einzigen Block selbst. Es ist die Schicht dazwischen — Menü und Klebstoff.

Installation

Was in den mods-Ordner gehört.

Alles für Minecraft 26.2 und Fabric. Litematica und Baritone sind optional im technischen Sinn — ohne sie startet der Mod, kann aber nichts anzeigen bzw. nichts bauen.

Wichtig: die richtige Baritone-Variante

Der standalone-Build funktioniert nicht.

Baritone wird in drei Varianten gebaut. In standalone entfernt Baritones eigener ProGuard-Lauf die Keep-Regel für baritone.api.** — dort heißen alle API-Methoden nur noch a(), b(), c() und kein anderer Mod kann sie aufrufen. Nutzbar sind api und unoptimized.

Empfohlen: auf meteorclient.com der Download-Button „*Baritone [26.2]". Das ist der eigenständige Fork von MeteorDevelopment — der volle Meteor Client muss nicht installiert werden.

Landet doch ein standalone-Build im Ordner, stürzt nichts ab: der Klick meldet dann „Diese Baritone-Variante hat kein API-Paket".

  1. Fabric installieren

    Fabric Loader für Minecraft 26.2 einrichten und einmal starten, damit der mods-Ordner existiert.

  2. Abhängigkeiten ablegen

    Fabric API, MaLiLib + Litematica und Baritone (api oder unoptimized) in den mods-Ordner kopieren.

  3. autobuild-gui-0.1.0.jar dazu

    Die JAR von hier daneben legen — sie ist client-seitig, auf dem Server muss nichts installiert werden.

  4. Welt betreten, B drücken

    Das Menü öffnet sich. Optional: config/autobuildgui.json steuert closeScreenOnBuildStart und materialCheckEnabled.

Ehrlich gesagt

Wo der Mod an seine Grenzen kommt.

  • Kein Prozent-Fortschritt

    Baritones IBuilderProcess gibt keine Fortschritts-Auskunft. Deshalb zeigt der Balken „läuft" statt einer Zahl.

  • Material-Check ist pessimistisch

    Litematica zählt den Bedarf für einen Bau von Null. Ein halb fertiges Placement verlangt darum mehr Material, als tatsächlich noch nötig ist. Im Creative-Modus wird gar nicht geprüft.

  • Nur Client-Seite

    Der Mod sendet keine eigenen Netzwerkpakete. Auf Servern gelten dieselben Regeln wie für Baritone selbst — siehe Nutzungsbedingungen.
