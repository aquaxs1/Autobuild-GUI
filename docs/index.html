What the mod does

Six things, no more.

Autobuild GUI is deliberately small: it reads what Litematica has loaded, checks your inventory and hands the job to Baritone. Everything else those two do themselves.

Hotkey

A menu at the press of a key

B opens the list — mid-game, without a chat command. The key is rebindable under Options → Controls.

Overview

Every placement at a glance

Every row shows name, dimensions and block count. The search box filters by name as you type — even with twenty schematics loaded.

Material-Check

Tells you beforehand what is missing

If the inventory falls short, the row reads "N blocks missing" and the click is locked — rather than getting stuck halfway through.

One click

A click starts the build

Baritone gets exactly that placement and the menu closes. No counting indices, no #build with coordinates.

Control

A running indicator you can stop

Open the menu again and the running placement shows a bar and a red ✕. Only ever one build runs; a new one cancels the old one cleanly.

Robust

Does not crash when something is missing

Without Litematica or Baritone the menu still opens and says in plain words which mod is missing. Both are genuine soft dependencies.

How it works

Three mods, one chain.

Autobuild GUI does not place a single block itself. It is the layer in between — menu and glue.

Litematica

Loads the schematic

You load your .litematic file as usual and put the placement into the world.

  • A running bar rather than invented percentages

    The bar travels instead of showing a number: Baritone's builder API reports no progress. A made-up percentage would be worse than none.

    missing

    A red row means locked

    If material is missing, the row is blocked rather than started. The click checks again — nothing is ever built on stale data.

  • One click, no dialog

    Click a row, the menu closes, Baritone runs. Press B again to see the running build with an ✕ to cancel.

Installation

What belongs in the mods folder.

Everything for Minecraft 26.2 and Fabric. Litematica and Baritone are optional in the technical sense — without them the mod starts, but it has nothing to show and nothing to build with.

Important: the right Baritone variant

The standalone build does not work.

Baritone is built in three variants. In standalone, Baritone's own ProGuard run removes the keep rule for baritone.api.** — every API method there is called just a(), b(), c() and no other mod can call them. The usable ones are api and unoptimized.

Recommended: on meteorclient.com, the download button "*Baritone [26.2]". That is the standalone fork by MeteorDevelopment — the full Meteor Client does not have to be installed.

If a standalone build ends up in the folder anyway, nothing crashes: the click then reports "This Baritone build has no API package".

  1. Install Fabric

    Set up Fabric Loader for Minecraft 26.2 and start it once, so that the mods folder exists.

  2. Drop in the dependencies

    Copy Fabric API, MaLiLib + Litematica and Baritone (api or unoptimized) into the mods folder.

  3. Add autobuild-gui-0.1.0.jar

    Put the JAR from here alongside them — it is client-side, nothing has to be installed on the server.

  4. Enter a world, press B

    The menu opens. Optional: config/autobuildgui.json controls closeScreenOnBuildStart and materialCheckEnabled.

Honestly

Where the mod hits its limits.

  • No percentage progress

    Baritone's IBuilderProcess gives no progress information. That is why the bar shows "running" instead of a number.

  • The material check is pessimistic

    Litematica counts what a build from zero needs. A half-finished placement therefore asks for more material than is actually still required. In creative mode nothing is checked at all.

  • Client-side only

    The mod sends no network packets of its own. On servers the same rules apply as for Baritone itself — see the terms of use.
